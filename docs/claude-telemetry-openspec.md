# OpenSpec: локальная телеметрия Claude в LLM Usage

Обновлено: 2026-10-07. Статус: **реализовано и проверено локально**. Change ID: `claude-session-telemetry`.
Рабочая ветка: `feat/claude-cost-parity`, [PR #29](https://github.com/RunGuitarMan/llm-usage-widget/pull/29), версия поставки **1.6.1**. Пользователь 2026-10-07 выбрал 1.6.1 и разрешил commit/push, merge и выпуск через штатный Release workflow на main. Первоначальная версия исправлений расчёта — 1.5.5; новые телеметрические оценки не меняют этот алгоритм.

## Proposal — результат для пользователя

LLM Usage по желанию пользователя принимает локальные API-события Claude Code, хранит их по сессиям, дополняет окно чата длительностью запросов, ошибками, служебными вызовами и сверкой цены. В настройках видны включение приёмника, фактическое поступление событий и экспорт диагностического ZIP за период либо выбранные сессии. Тексты чата, инструментов, HTTP-заголовки и конфиг Claude в диагностическое хранилище и архив не попадают.

Основание: в [расследовании стоимости](claude-cost-parity.md) 26 событий выявили два служебных вызова, отсутствующих в 24 основных запросах JSONL: $1.3015691 + $0.00684 = $1.3084091. Прототип — `Scripts/claude-usage-capture.py`; переносить его идеи и фикстуры, а не запускать Python из продукта.

В первой реализации принимаем **OTLP logs/events**, как в проверенном сборщике. Полные beta-traces, span-деревья, сырые API bodies, удалённый сбор и изменение источника основной стоимости не входят в этот change. Метки и текст UI — RU/EN. Для пользователя название функции: «Телеметрия Claude».

## Requirements — обязательные требования

### R1. Подключение и управление

- MUST: по умолчанию выключено. При первом обычном запуске с новой функцией один раз предложить подключение: назначение, состав данных, путь к настройкам и кнопки «Настроить» / «Не сейчас». Фоновый login-запуск откладывает предложение до открытия интерфейса. Отказ запоминается; повторное подключение доступно в настройках.
- MUST: в настройках переключатель «Принимать телеметрию Claude», кнопка настройки подключения, статус и время последнего API-события, число полученных запросов/ошибок, экспорт и управление хранением. Первое включение открывает preview подключения, если настройки ещё не готовы. Переключатель управляет приёмником и НЕ служит скрытым согласием на изменение файла Claude.
- MUST: слушать только `127.0.0.1`, сохранять выбранный порт между запусками. Предпочесть 4318; при первом подключении занятый порт не отбирать, предложить свободный и показать его в добавляемом env. Уже настроенный endpoint самовольно не менять. Нельзя переключать ранее настроенный порт лишь потому, что он занят после рестарта: показать конфликт и оставить env прежним. Один владелец listener; закрытие окна не останавливает menu-bar процесс, выход из приложения останавливает приём.
- MUST: выключение немедленно прекращает приём/новую запись, не удаляет историю и не редактирует env. Сохранённая аналитика остаётся доступной с пометкой «Сбор выключен». UI объясняет, что во время выключения/выхода события могут не сохраняться; их последующее восстановление не обещается.
- MUST: запуск Claude остаётся корпоративным способом, без команды `claude` и без перезапуска чужих процессов. После настройки предложить открыть новую сессию обычным способом. Успешная запись env не означает, что корпоративный launcher/managed settings применил эти значения.

### R2. Добавление env — неизменность существующего конфига

Целевой файл по умолчанию: **`~/.claude/settings.json`** (во множественном числе; не `setting.json` и не `~/.claude.json`). При явно выбранном другом пользовательском конфиге показать полный путь и применить те же проверки. Не искать и не редактировать автоматически проектные/managed settings.

**Главный инвариант:** разрешены только вставка отсутствующих пар в корневой `env` или создание `env`, если его нет. Существующие ключи, значения и остальные байты документа не перезаписывать. Равное существующее значение — no-op; любое конфликтующее значение — отказ от всей автоматической записи, без частичного добавления. Не заменять значения, даже если они мешают подключению или включают чужую телеметрию.

Профиль добавляемых строковых значений для обычного нового подключения (`<port>` — сохранённый порт):

```json
{
  "CLAUDE_CODE_ENABLE_TELEMETRY": "1",
  "OTEL_LOGS_EXPORTER": "otlp",
  "OTEL_EXPORTER_OTLP_LOGS_PROTOCOL": "http/json",
  "OTEL_EXPORTER_OTLP_LOGS_ENDPOINT": "http://127.0.0.1:<port>/v1/logs",
  "OTEL_LOGS_EXPORT_INTERVAL": "1000",
  "OTEL_METRICS_EXPORTER": "none",
  "OTEL_TRACES_EXPORTER": "none",
  "CLAUDE_CODE_ENHANCED_TELEMETRY_BETA": "0",
  "ENABLE_ENHANCED_TELEMETRY_BETA": "0",
  "OTEL_LOG_USER_PROMPTS": "0",
  "OTEL_LOG_ASSISTANT_RESPONSES": "0",
  "OTEL_LOG_TOOL_DETAILS": "0",
  "OTEL_LOG_TOOL_CONTENT": "0",
  "OTEL_LOG_RAW_API_BODIES": ""
}
```

Этот блок — значения **внутри env**, не замена всего settings.json. Не добавлять глобальный `OTEL_EXPORTER_OTLP_ENDPOINT`, не менять credentials, proxy, permissions, hooks, model, команды или shell profiles.

Порядок безопасной транзакции MUST:

1. Прочитать свежие байты/идентичность/метаданные файла; строгий JSON parser с обнаружением повторяющихся ключей и диапазонов в исходном тексте. Корень и существующий env должны быть объектами. Пустой, повреждённый, нестандартный JSON, `env: null`, дубликаты, чужое владение, symlink/необычный тип файла/ненадёжный путь — ничего не писать, показать понятную причину и ручную инструкцию. Не исправлять такой файл автоматически.
2. Проверить не только совпадения ключей, но и маршрутизацию: существующий корпоративный/global OTLP endpoint, headers/helper или beta tracing может означать, что добавление per-signal endpoint перенаправит чужой сбор. При неоднозначности ничего не менять. Можно включить listener без правки файла и показать ручную настройку; credentials не выводить в preview/logs.
3. Сформировать чистый план вставок по диапазонам JSON, не regex-замену и не полную сериализацию `Dictionary`. Сохранить порядок, отступы, переводы строк, escape-последовательности и точное представление старых чисел. Повторно распарсить результат; доказать, что семантическая разница — исключительно разрешённые добавления, а старые фрагменты сохранены побайтно.
4. Показать пользователю путь, **только добавляемые пары**, существующие совпадения/названия конфликтующих ключей и факт резервного копирования. Выполнять запись только после «Добавить переменные». Отказ/закрытие — ноль записей, включая создание каталога и backup.
5. После согласия повторно проверить исходные байты и identity. Любое изменение после preview отменяет старый план; строится новый для нового подтверждения. Сериализовать собственные операции, использовать file coordination/lock и проверить precondition непосредственно перед заменой. Не обещать, что advisory lock остановит произвольный внешний writer; при обнаруженном внешнем изменении не перезаписывать и не делать слепой rollback.
6. Для существующего файла создать отдельную резервную копию исходных байтов с доступом только владельцу; backup не включать в телеметрию/ZIP и не логировать его содержимое. Не писать основной файл, если backup не создан и не проверен. Для отсутствующего файла создать только минимальный объект с env; убедиться, что файл не появился между проверкой и созданием (exclusive create).
7. Записать подготовленный файл во временный соседний файл, проверить и синхронизировать, сохранить исходные разрешения/владельца/ACL/xattrs, атомарно заменить оригинал. Новые файлы — 0600, новый каталог — 0700. Повторная проверка результата обязательна. Ошибка не должна оставлять частично записанный JSON; восстановление возможно только после проверки, что не затрёт последующее чужое изменение. Backup остаётся доступным для ручного восстановления.
8. Сохранить квитанцию операции: путь локально, hash до/после, список только добавленных ключей и backup. Не сохранять копии существующих env-значений в журнал приложения. Повторная настройка с теми же значениями — полное отсутствие изменений/нового backup.

При выключении или удалении телеметрии env автоматически **не удаляется и не откатывается**: это отдельное изменение конфига, которого пользователь здесь не разрешал. В продукте показать краткую инструкцию для ручного отключения экспорта в Claude.

### R3. Приём и приватность до записи

- MUST: встроенный Swift listener (`Network.framework`), `POST /v1/logs`, OTLP/HTTP JSON. Отдельный сервис от `UpdateArchiveServer`; не расширять update-сервер до постоянно работающего общего сервера. Никаких Python/Node/дополнительного daemon в поставке.
- MUST: ограничить заголовки (16 KiB), wire/body после распаковки (16 MiB), число событий (10 000/пакет), соединения (4), ожидание (10 s), очередь и скорость. Потоковый приём сегментов; корректно обрабатывать Content-Length, chunked и gzip с лимитами либо явно отклонять неподдерживаемый транспорт. Предпочтение для v1 — поддержать все три. Не слушать внешние интерфейсы, не включать CORS; браузерный Origin отклонять.
- MUST: фильтровать в памяти **до любого disk write, системного лога или диагностики исключения**. Raw OTLP, headers, payload ошибки, любые свободные тексты и неизвестные attributes не сохраняются. Не копировать поля потому, что они находятся в `resource`/`body`. `body` допустим только как строго распознанное имя события.
- MUST: сохранять только `api_request` и `api_error`; остальные события игнорировать, отдельно считать их количество. Не собирать prompts, assistant responses, tool events или spans ради связывания: request ID достаточно для поддерживаемого сценария; без него показать ограничение.
- MUST: числа — конечные неотрицательные, целые счётчики с проверкой диапазона Int64 и переполнения сумм; missing не равен 0. Присутствие `cost_usd_micros` и `cost_usd` не означает две цены. Каноническая оценка — decimal `cost_usd`, micros — fallback и контроль округления.
- MUST: отсутствие/невалидный session ID не разрешает приписать событие текущему чату. Считать его отдельным несопоставленным событием; не сохранять сырой пакет «для последующего разбора».
- MUST: ACK успеха — только после успешной записи допустимых событий; повторы после сбоя не дублируются. Обрабатывать partial success/ошибки OTLP без содержимого исходного запроса. Полностью пустой/игнорируемый пакет не считается поступлением API-телеметрии.

### R4. Данные и хранение по сессиям

Разрешённая схема `schemaVersion=1` (необязательные поля сохраняют отсутствие; документ плана — Markdown, само хранилище — структурированные JSONL/JSON):

| Группа | Поля |
|---|---|
| Идентичность | валидный session UUID, event kind, ограниченные request_id/client_request_id; локальный event key |
| Время | event timestamp, receive timestamp, event.sequence при наличии, duration_ms |
| Учёт | model, input/output/cache-read/cache-write, cost_usd, cost_usd_micros |
| Контекст | версия Claude, speed, безопасная категория query_source |
| Ошибка | HTTP status_code, attempt; категория из фиксированного enum, unknown при недостатке данных |

`query_source` — allowlist известных категорий (`repl_main_thread`, `generate_session_title`, `rename_generate_name`, известные built-in категории); пользовательские имена заменяются на `other`. Model/ID имеют лимиты длины и проверку формы; они не считаются анонимными до экспорта. Свободный `error` не хранить; не выводить текст ошибки через String(describing:) над исходным payload.

- MUST: actor-хранилище в `~/Library/Application Support/LLMUsage/Telemetry/`, отдельно от WidgetKit snapshots. На каждую сессию — каталог с безопасным ключом, `events.jsonl` и атомарный `summary.json`; общий восстанавливаемый индекс. Пути строятся приложением, не из произвольного request ID. Каталоги 0700, файлы 0600; одновременный export читает согласованный snapshot.
- MUST: хранить UTC; дневной выбор использует часовой пояс приложения и время события. Receive time — отдельное поле; при его использовании вместо отсутствующего event time указывать это явно. Resume дополняет ту же сессию; `/clear` создаёт отдельную. Сброс event.sequence не создаёт дубль/потерю.
- MUST: отделить дедупликацию доставки от группировки API-вызовов. Устойчивый fingerprint нормализованного события без receive time удаляет повтор одного пакета и переживает рестарт. Одного event.sequence или request ID недостаточно; несовместимые данные одного идентификатора отмечаются конфликтом, не суммируются автоматически. Событие ошибки не превращать в дополнительный успешный платный запрос.
- MUST: восстановление после оборванной последней JSONL-строки и перестроение индекса без потери валидных предыдущих событий. Записывать интервалы работы/паузы, отброшенные/повреждённые события и усечение, чтобы частичный сбор не выглядел полным.
- MUST: по умолчанию хранить 30 дней, глобальный лимит 100 MiB; настройки 7/30/90 дней, удалить выбранную сессию/все данные с подтверждением. Очистка по age, затем по oldest received; активные данные нельзя молча усекать — фиксировать разрыв покрытия. Если квота не освобождена, приём показывает ошибку хранения. Отключение не удаляет данные.

### R5. Настройки: работает ли подключение

Статусы: **«Выключено»**, **«Приёмник готов, API-событий ещё нет»**, **«Получаем API-события»**, **«Ожидаем новые события — последнее …»**, **«Ошибка подключения/хранения»**. У «Получаем» короткое окно активности 60 s; затем нейтральное ожидание, а не красная ошибка. Маркер дублировать текстом, не одним цветом.

Разделять: listener ready; последний валидный OTLP-пакет; последнее принятое API-событие; успешную запись на диск. Показать API-запросы, API-ошибки, несопоставленные/отвергнутые события и размер хранения. Искусственный local self-test не зажигает индикатор «Claude отправляет». При тишине доступна краткая проверка env/новой сессии/конфликта порта/managed settings; не объявлять причиной прокси без доказательств.

### R6. Дополнение окна чата

- MUST: раздел «Телеметрия» появляется для Claude-сессий с сохранёнными данными; при включённом сборе без данных — компактное состояние ожидания. Для остальных агентов интерфейс не меняется. Поздние события обновляют только связанную сессию; работа вне main thread, debounce, отмена при закрытии чата.
- MUST: связывать API-событие и дедуплицированный JSONL-запрос по **session ID + request_id** с проверкой модели и счётчиков. `client_request_id` применять только если обе стороны его имеют. Время/соседство/одинаковые токены не являются доказательством связи. При отсутствии/неоднозначности ID показывать отдельную строку «Не сопоставлено» без ссылки на случайное сообщение.
- MUST: у сопоставленного обращения — длительность API, оценка Claude, оценка LLM Usage, расхождения счётчиков/цены. Длительность — время данного API-вызова, не гарантированное «чистое время генерации»; сумму параллельных duration не выдавать за wall time. Не высчитывать TTFT, задержку сети или число retries без соответствующих полей.
- MUST: служебные вызовы — отдельный список с понятными названиями (например «Название сессии»), моделью, временем, токенами и ценой. Не создавать пользовательские сообщения. Подтверждённые события детализируют уже существующую строку `ClaudeSessionAccounting`, но НЕ начисляются второй раз.
- MUST: API-ошибки — отдельные события со status/attempt/duration, без сырого сообщения ошибки. Attempt показывать как переданный счётчик попыток; не дорисовывать отсутствующие попытки и их стоимость.
- MUST: сохранять основной расчёт 1.5.5 по JSONL + валидному modelUsage и текущим тарифам. Телеметрия — отдельная оценка/сверка. Для разных тарифов или неполного охвата писать причину/неопределённость, а не объявлять баг автоматически. Сравнивать одинаковые наборы запросов; при наличии полного snapshot сверять и охват сессии. Полнота всех скрытых вызовов не выводится из одного совпадения 24/24.
- MUST: показывать «Сопоставлено N из M основных запросов», интервалы сбора и частичность. Ноль полученных событий — не нулевой расход. TTL-разбивка не выдумывается из стандартного API-события. Полные totals и дневной срез различать, накопительный modelUsage по дням не дублировать.

### R7. Обезличенный экспорт для анализа

- MUST: одна кнопка «Экспорт диагностики…» в настройках: режим **Период** (сегодня / последние 7 дней / свои даты) или **Сессии** (список по датам, модель, время, число событий; поиск и множественный выбор). Из чата — shortcut с выбранной сессией. Перед сохранением показать диапазон/часовой пояс, количество сессий и состав архива. `NSSavePanel`, отмена без итогового файла.
- MUST: ZIP `manifest.json`, `sessions/<alias>/events.jsonl`, `accounting.json`, `summary.json`, краткий `README.md`. В manifest — версия схемы/app/Claude/helper, временной охват и пропуски, counts, timezone, причина неполноты. Accounting — только числовая проекция JSONL/modelUsage, версии/безопасные числовые ставки расчёта и результаты сверки; не весь transcript, конфиг, pricing receipt или директория хранилища.
- MUST: использовать DTO с allowlist, **не `SessionTranscript.exportText`** (он содержит чат и raw records) и не «zip всей папки». Экспортировать только явно выбранные сессии/события. Для периода накопительный итог помечать как контекст всей сессии, не как расход дня.
- MUST: новые случайные псевдонимы session/request/client ID для каждого архива, согласованные между файлами; таблица соответствий только в памяти и никогда внутри ZIP. Сохранять числовые счётчики/ставки для воспроизводимости. Публичные известные модели можно оставить; неизвестные корпоративные model aliases заменять на `model-N`, сохраняя связь с числовыми тарифами. Project paths, заголовки сессий, пользователь/hostname/account/repo, endpoint/headers, имена custom agents и любые backup-файлы исключить.
- MUST: точные временные метки нужны для границ дней и сверки; оставить UTC и выбранный timezone, сообщить об этом в preview. Обезличивание удаляет прямые идентификаторы, но не обещает невозможность косвенного сопоставления по времени/числам.
- MUST: временные файлы приватные, очищаются после успеха/ошибки/отмены. Никаких автоматических upload/send. Ошибки записи и нехватка места не дают «успешный» неполный архив. Для сессии без JSONL экспортировать телеметрию с явным отсутствием сравнения, а не молча исключать её.

## Design — границы компонентов

| Компонент | Ответственность |
|---|---|
| `ClaudeTelemetryCoordinator` | настройки, lifecycle, on/off, observable статус, изоляция demo/review |
| `ClaudeTelemetryReceiver` | только loopback HTTP/OTLP transport, лимиты, ACK/backpressure |
| `ClaudeTelemetrySanitizer` / DTO | allowlist, типы, отсутствие raw text/headers, версия схемы |
| `ClaudeTelemetryStore` (actor) | отдельные сессии, dedup, индекс, recovery, retention, согласованное чтение |
| `ClaudeSettingsEnvEditor` | inspect → preview → явное согласие → add-only transaction → receipt |
| `ClaudeTelemetryReconciler` | связь с TranscriptRequest, сравнение одинакового охвата, service/error rows |
| `ClaudeTelemetryExporter` | числовые DTO, псевдонимы, ZIP и manifest; независим от текстового экспорта чата |

Точки интеграции: `LLMUsageApp`/`UsageStore`, `UsageSettingsView`, `SessionTranscript` (отдельные metadata), `TranscriptAnalyticsView`/`TranscriptTimingView`; переиспользовать контракты `ClaudeSessionAccounting`, `TranscriptCostService`/архив тарифов. Не смешивать OTel события с raw transcript records. WidgetKit не слушает порт и не читает telemetry store. Учитывать `Package.swift`, генератор Xcode-проекта и локализацию.

## Scenarios — приёмочные проверки

1. **GIVEN** settings с permissions/hooks/proxy/необычным форматированием **WHEN** согласие на подключение **THEN** добавлены только отсутствующие env-пары; старые сегменты побайтно прежние, backup точен. Env отсутствует/файл отсутствует/пустой объект проверяются отдельно.
2. **GIVEN** существующее значение отличается, env=null, duplicate keys, invalid JSON, symlink, read-only или backup failure **WHEN** подключение **THEN** исходный файл не изменён. При no-op/отказе не создаётся backup; повторная настройка идемпотентна.
3. **GIVEN** файл изменён после preview/перед commit либо появление файла во время create **WHEN** запись **THEN** новый чужой файл не затёрт; устаревший план отменён. Injected failure на этапах write/fsync/rename/postcheck не оставляет обрезанный JSON и не запускает слепой rollback.
4. **GIVEN** listener без реального API-события, пустой пакет, только tool events либо self-test **THEN** UI не говорит «Получаем API-события». Успешное событие включает индикатор; тишина превращает его в нейтральное ожидание; disk failure виден отдельно.
5. **GIVEN** пакет с prompt/response/tools, Authorization, account IDs, paths, секретами и неизвестными attributes **WHEN** приём и export **THEN** контрольных секретных строк нет ни в telemetry-файлах, ни в ZIP, ни в логах приложения. Текстовый экспорт чата не используется.
6. **GIVEN** повторная доставка, out-of-order события, restart/resume/reset sequence, совпавший request ID с разными данными **THEN** нет двойного счёта; конфликт отмечен; две параллельные сессии изолированы; нет session ID — нет случайной привязки.
7. **GIVEN** обезличенная фикстура из расследования **THEN** 24 main + 2 служебных, суммы 1.3015691 / 0.00684 / 1.3084091; основной итог не вырос второй раз. Удвоенные пользовательские тарифы сохраняют app-оценку, отличие от Claude объясняется тарифом.
8. **GIVEN** сбор с середины сессии, ошибки, пропуски, отсутствие request ID/JSONL, пересечение полуночи, DST и часовые пояса **THEN** корректны охват и выбор дней, нет ложного совпадения полной цены или выдуманного wall time/retry count.
9. **GIVEN** обрыв JSONL, повреждённый индекс, превышение retention/quota, удаление во время export **THEN** восстановление/согласованность/partial coverage работают; UI не зависает. Несколько пакетов подряд не заставляют перечитывать все чаты.
10. **GIVEN** RU/EN, светлая/тёмная тема, компактное окно **THEN** доступны onboarding/settings/status/export/session telemetry, ошибки и пустые состояния. Review использует только synthetic env/store/settings; реальные `~/.claude/settings.json` и пользовательская телеметрия не затрагиваются.

## Фактическая реализация

- `StrictJSON` сохраняет диапазоны исходных байтов и отвергает повторные ключи. `ClaudeSettingsEnvEditor` вставляет только отсутствующие пары, блокирует всю запись при конфликте маршрутизации, проверяет identity/bytes до commit и непосредственно перед replace. Preview не создаёт файл, каталог или backup. Только отдельная кнопка «Добавить переменные» вызывает транзакцию: NSFileCoordinator + advisory lock, проверенный backup 0600, соседний временный файл, сохранение metadata/ACL/xattrs, fsync, атомарная замена и postcheck. Отсутствующий файл создаётся через exclusive link; чужое изменение не откатывается вслепую. Квитанция содержит пути, hashes и добавленные ключи, без значений старого env.
- Встроенный `Network.framework` listener принимает только `127.0.0.1`, `POST /v1/logs`, JSON. Поддержаны Content-Length, chunked и gzip; лимиты 16 KiB headers, 16 MiB wire/body после распаковки, 10 000 records, 4 соединения, 10 s, 120 запросов в минуту. Парсинг сериализован вне main thread, ACK следует за сохранением. Origin, неоднозначный framing и неподдержанные кодировки отвергаются. Ответы содержат только контролируемые сообщения и partial-success counts.
- DTO оставляет только `api_request`/`api_error` и разрешённую metadata. Тексты, tools, произвольные error strings, resource attributes и headers не передаются в хранилище. Числа проверяются на тип/знак/переполнение; отсутствующие значения отличаются от нуля. Decimal cost — основной, micros — fallback. Fingerprint исключает receive time и стабилен после сериализации дробных UTC timestamps; исходные OTLP nanoseconds сохраняются отдельным числовым полем.
- Actor хранит `Telemetry/<session UUID>/events.jsonl`, summary/index и интервалы/причины неполноты. Файлы 0600, каталоги 0700. Доставка дедуплицируется отдельно от конфликтов call ID. Обрыв последней строки и повреждение metadata восстанавливаются по валидным событиям. По умолчанию 30 дней/100 MiB; возрастная очистка предшествует удалению oldest received. Удаление/усечение отмечается; снимок экспорта остаётся согласованным при последующих изменениях.
- RU/EN onboarding и настройки используют производственные sheets. Переключатель управляет listener, а согласие на env остаётся отдельным действием. API activity живёт 60 s, затем становится нейтральным ожиданием; empty/tool packets не включают её. Показаны времена packet/API/write, counts, размер, retention и подтверждение удаления. Порт стабилен после настройки; занятый сохранённый порт даёт ошибку. Review/demo получают отдельные prefs, временный store/config и свободный порт.
- В чате сопоставление требует session + request/client ID и проверяет модель/все четыре счётчика. Служебные вызовы и ошибки выделены отдельно; ни один telemetry event не добавляется к стоимости. Сравнение выполняется на одинаковом наборе запросов; snapshot с нулевым overhead также распознаётся. Обновления и очистка инвалидируют только изменившиеся сессии, сверка работает вне main thread.
- Экспорт выбирает период либо несколько сессий, фиксирует snapshot и использует NSSavePanel. ZIP собирается непосредственно из allowlist DTO: manifest, события, числовые accounting/summary и README. Session/request/client aliases новые в каждом архиве, все модели заменены на `model-N`, числовые ставки сохранены. Нет raw transcript/exportText, settings, backup или таблицы соответствий. Накопительные значения явно помечены контекстом всей сессии; отсутствие JSONL не исключает telemetry. Архив сохраняется через приватный временный файл, fsync и атомарный replace; загрузки на сервер нет.

## Практические ограничения

- Подключение opt-in. При остановленном приложении/выключенном приёмнике доставка не гарантируется; скрытые вызовы нельзя восстановить из отсутствующих событий. Совпадение видимых запросов не доказывает полного охвата.
- Корпоративный launcher/managed settings может переопределить env. Фактическую доставку подтверждают API-события; реальная оплачиваемая сессия и реальный settings.json для этой разработки не использовались.
- Поддержан OTLP HTTP/JSON logs, без protobuf/gRPC, beta traces и raw API bodies. Chunk extensions/trailers, concatenated gzip members и Expect явно отвергаются. Лимиты и отказ по переполнению не скрываются успешным ACK.
- Advisory lock/file coordination не блокируют произвольный сторонний writer. Проверки максимально приближены к replace; при обнаруженном изменении требуется новый preview, backup остаётся для ручного восстановления. Абсолютная защита от некооперативной записи ровно между последней проверкой и rename не обещается.
- События записываются атомарной заменой файла сессии. Это ограничивает повреждение хвоста, но очень большие сессии требуют больше I/O; при превышении лимита/недостатке места возвращается ошибка. ZIP ограничен 256 MiB; временная запись требует дополнительного свободного места.
- Временные метки экспортируются в UTC с микросекундной точностью Foundation Date, OTLP nanoseconds сохраняются отдельно при наличии. Время и числовые показатели допускают косвенное сопоставление, о чём предупреждает preview.
- Локальный Command Line Tools не содержит XCTest. Общие сценарии проверяются portable runner; полный `swift test` выполнен CI с Xcode на `5b82653`; финальная версия также проходит обязательный CI.
